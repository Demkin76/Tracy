# Tracy: выбрать агента и запустить свою копию

Tracy на Devnet объединяет каталог с историей действий и исполнение личных копий агентов.
Доступны две управляемые платформой программы: выплаты по списку и выплаты по расписанию.
Они выполняют заданные инструкции. Встроенного LLM и загрузки произвольного кода автора нет.

## Для пользователя

1. Откройте http://127.0.0.1:8000/explore.
2. Откройте Atlas или Sentinel, изучите историю и описание исполняемой программы.
3. Нажмите **Use agent**. Если необходимо, войдите: выбранный агент сохранится.
4. Задайте название личной копии, получателей, суммы, разовый и дневной лимиты.
5. Для расписания задайте интервал и число циклов. Первый цикл начинается сразу после запуска.
6. Подтвердите настройки и нажмите **Install agent**. Установка ещё не переводит средства.
7. В **Installed agents** нажмите **Run once** или **Start schedule**.
8. Откройте **Inspect proof** в истории запуска. Проверка доступна на странице квитанции.

Новый экземпляр имеет отдельный ключ, собственные правила и пустую приватную историю.
Изменения исходного предложения не меняют уже установленные копии.
Средства сейчас выделяет общий тестовый кошелёк Tracy; собственный кошелёк подключать не требуется.
Бюджет экземпляра, общая квота аккаунта и квота платформы проверяются перед каждым переводом.
Комиссия сети оплачивается отдельно и не входит в лимит суммы перевода.

**Stop agent** выключает экземпляр, расписание и отменяет оставшуюся очередь.
Уже отправленная транзакция может завершиться после остановки.
**Resume agent** только разрешает новые действия: расписание нужно запустить явно.
Для изменения списка выплат остановите текущую работу и откройте **Edit payout instructions**.
Лимиты меняются через **Edit limits & profile**.

При отказе или ошибке прекращается весь текущий запуск и останавливается расписание.
Проверьте уже выполненные строки перед новым запуском: новый Run once повторяет весь список.
PENDING/WAITING автоматически проверяется сервером; не нужно создавать повторную выплату.
Пропущенные при выключенном сервере интервалы не воспроизводятся пачкой.
Закрытие вкладки не прекращает исполнение; выключение сервера приостанавливает его.

## Для автора

Создайте собственную идентичность агента в **My agents**, подключите внешний бот через SDK,
накопите проверяемую историю и при желании опубликуйте профиль с явным согласием на раскрытие истории.

В **Offer a runnable agent** выберите поддерживаемую программу и включите установку.
Для появления Use agent профиль должен быть опубликован и активен.
Опишите программу точно: на сервере выполняется выбранная программа Tracy,
а не загружается код вашего внешнего бота. Исходная история не является сертификацией этой программы.
Новая публикация предложения увеличивает версию. Уже установленные копии сохраняют свою версию.

## Как устроено исполнение

- SQLite хранит предложения, установки, планы и очередь запусков.
- Каждый экземпляр получает Ed25519-ключ, производный от серверного ключа через HMAC с отдельным контекстом.
  Это управляемый платформой ключ; пользователь не подписывает каждую выплату в браузере.
- Фоновый исполнитель использует тот же ActionService, ограничения, проверку Devnet и подписанные квитанции.
- Установка идемпотентна по паре owner/request_id. Повтор с другими параметрами отклоняется.
- Run once идемпотентен по паре instance/request_id. У каждой строки постоянный request_id.
- После перезапуска уже записанное действие перечитывается, а не отправляется заново.
- Незавершённый перевод блокирует последующие строки и следующий цикл.
- Один процесс обслуживает одну базу; запуск второго блокируется файлом блокировки.
- Резервная копия должна включать SQLite и соответствующий .env: он нужен и для ключей личных копий.

Основные API: POST /v1/installations, GET /v1/installations,
PUT /v1/installations/{id}/plan, POST /v1/installations/{id}/runs,
GET /v1/installations/{id}/runs, POST /v1/installations/{id}/start,
POST /v1/installations/{id}/stop, PUT /v1/agents/{id}/offer.
Изменение плана требует expected_revision, установка — expected_version предложения.

## Границы версии

Это локальная версия с настоящими транзакциями Solana Devnet и тестовыми средствами.
Для внешнего доступа нужны сервер, домен и HTTPS; текущие localhost-ссылки работают только на этой машине.
Платные услуги, Mainnet, пользовательские депозиты и произвольные торговые/LLM-агенты в этот релиз не входят.
